# ۴. بررسی سازگاری حرفه‌ای با MikroTik

## نتیجه کلی
پروژه برای استفاده عملی روی RouterOS 6 و 7 طراحی شده و مسیر اصلی (mangle + policy routing) با هر دو نسخه هماهنگ است. نقاط حساس نسخه ۷ (جدول با `fib` و پارامتر `routing-table`) به‌صورت صریح پوشش داده شده‌اند.

## ماتریس سازگاری

| قابلیت | ROS 6 | ROS 7 | توضیح |
|--------|-------|-------|------|
| اتصال API باینری (8728) | ✅ | ✅ | go-routeros/v3 |
| تشخیص نسخه | ✅ | ✅ | `/system/resource/print` |
| mangle mark-routing | ✅ | ✅ | مشترک |
| پارامتر روت سفارشی | `routing-mark` | `routing-table` | انتخاب خودکار |
| لیست جدول‌ها | از mangle+route | از `/routing/table`+mangle+route | تجمیعی |
| ساخت جدول + fib | لازم نیست | ✅ | فقط وقتی IsV7 |
| DHCP leases | ✅ | ✅ | |
| اینترفیس VPN | ✅ (اگر در print بیاید) | ✅ | لیست type گسترش یافته |
| Container روی خود روتر | ❌ (معمولاً) | ✅ (7.4+) | محدودیت سخت‌افزاری |

## جریان داده (حرفه‌ای)
1. کاربر/ادمین درخواست تغییر اینترنت می‌دهد.
2. قوانین mangle قبلی همان IP حذف می‌شود.
3. در v7 در صورت نبود جدول، با `fib` ساخته می‌شود.
4. قانون `mark-routing` + در صورت امکان exception شبکه داخلی اضافه می‌شود.
5. روت‌های جدول از طریق نگاشت سوپرادمین (جدول↔اینترفیس) و gateway تشخیص‌داده‌شده اعمال می‌شوند.

## نکات عملیاتی مهم
- **Gateway:** از dhcp-client (status=bound) و سپس route پیش‌فرض خوانده می‌شود. اگر اینترفیس VPN gateway دینامیک داشته باشد، ممکن است نیاز به تنظیم دستی gateway در روتر باشد.
- **Exception داخلی:** برای جلوگیری از قطع دسترسی به خود روتر، dst شبکه /24 مربوط به API_HOST با action=accept اضافه می‌شود.
- **نام جدول:** از کاراکترهای ساده و بدون فاصله استفاده کنید (مثلاً `to-vpn1`).
- **دسترسی API:** کاربر API نباید فقط read-only باشد.

## محدودیت‌های شناخته‌شده
1. ساخت جدول با UI فقط در v7 معنی دارد.
2. پنل بلاک کاربر را در settings نگه می‌دارد؛ برای بلاک شبکه واقعی می‌توان بعداً address-list/firewall اضافه کرد.
3. چند روتر همزمان در این نسخه پشتیبانی نمی‌شود (معماری تک‌روتر).
4. HTTPS داخلی ندارد؛ در صورت نیاز از reverse proxy استفاده کنید.

## توصیه‌های استقرار حرفه‌ای
- `DATA_DIR` را روی mount دائمی (USB/SSD) بگذارید تا settings و بکاپ‌ها از بین نروند.
- Envها را در `/container/envs` ست کنید؛ نیازی به rebuild ایمیج برای تغییر رمز/API نیست.
- قبل از production، روی یک روتر آزمایشی با همان نسخه ROS تست کنید.
- لاگ کانتینر را فعال نگه دارید: `logging=yes`.
